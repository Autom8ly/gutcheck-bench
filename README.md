# gutcheck-bench

**Run open System 1 decision models on your own 8 GB GPU.** A tool-neutral scorer, benchmarks, quantization patches and adapters for teams that need Jev-style typed decisions but can't send data to an external API.

> **Mostly AI-generated.** This repository and the accompanying articles were largely generated by our AI assistant, Autumn (primarily Claude, by Anthropic, with Autom8ly’s internal prompts and skills), directed by Mark Vange in response to specific use cases in high-compliance environments. All measurements were taken on real hardware (below), and everything needed to reproduce them is here.

📄 **Article:** [Jev is the best decision model. Here's what to run when you can't use it.](https://medium.com/autom8ly/jev-is-the-best-decision-model-heres-what-to-run-when-you-can-t-use-it-bb44e94946cf)

📄 **Follow-up:** [Kev gives the same answer every time. Until you batch it.](https://medium.com/autom8ly/kev-gives-the-same-answer-every-time-until-you-batch-it-6ba0134f7b75)

## What this is

[Jev](https://typesafe.ai) (TypeSafe) answers typed questions (pick one, yes/no, score) with probabilities instead of generated text. Within a week of its release, seven open-source look-alikes appeared. We ran 14 configurations of them, one at a time, on a single **RTX 4060 (8,188 MiB)**, and scored every one, plus Jev itself through TypeSafe's API, on the independent [jabr/classifier-benchmark](https://github.com/jabr/classifier-benchmark) v2 suite: 866 synthetic cases across 49 decision tasks, public domain (CC0).

## Stability and uncertainty

Follow-up measurements ([article](https://medium.com/autom8ly/kev-gives-the-same-answer-every-time-until-you-batch-it-6ba0134f7b75)): Kev-4B 4-bit reruns bit-identically one request at a time, but its probabilities drift once the server batches five or more concurrent requests (decisions barely move: 2 flips in 2,598 batched answers). Also 95% intervals (Kev 0.872, 0.850–0.894; gap to Jev 9.6 points, 7.5–11.8) and held-out automation rates. See [`stability/`](stability).

## The scorer

`gutcheck` is a small scorer for any `/v1/systemone` endpoint, written so that no tool under test grades itself.

- **Attribution:** its metric definitions (accuracy, binned calibration error, Brier score, confident-error rate, and coverage at an error budget) are **based on Kev's open-source scorer** (`kev/metrics.py`, `kev/benchmark.py` in [jaredpalmer/kev](https://github.com/jaredpalmer/kev), Apache-2.0, commit `105c76958d4c`). `gutcheck/metrics.py` is a smaller reimplementation of the subset we report.
- **Verification:** `python -m gutcheck.rescore <run dirs>` re-scores saved predictions and compares them with the original report. On all 14 of our first-round runs (recorded with Kev's scorer), gutcheck reproduced every reported metric exactly (largest difference 0).
- It needs only Python 3.11+ and numpy.

```bash
# score any /v1/systemone server
python -m gutcheck.benchmark --endpoint http://127.0.0.1:8008 --model kev-latest \
    --suite suites/jabr-v2.jsonl --out runs/my-tool

# hosted Jev: key from JEV_API_KEY (or GUTCHECK_API_KEY), or a file
python -m gutcheck.benchmark --endpoint https://api.typesafe.ai --model jev-latest \
    --suite suites/jabr-v2.jsonl --out runs/jev --api-key-file ~/.jev_key
```

## Reproduce

1. Check out each tool at the commit below and install it as its README says. Kev, SemIf and Nimble need the patches or adapters here to load 4-bit/8-bit models.
2. Start a tool's `/v1/systemone` server (or one of our adapters) and run `python -m gutcheck.benchmark` against it, or let the harness manage the server and memory measurement:

   ```bash
   harness/bench.sh kev-4b-4bit 8202 ~/tools/kev kev-latest suites/jabr-v2.jsonl -- \
       env KEV_QUANT=4bit KEV_FUSED=0 KEV_CUDA_GRAPHS=0 uv run python -m kev.serve --run jaredpalmer/kev-4b --port 8202
   ```

   `harness/run_jabr_v2.sh` has the exact command for every setup. Kev-9B also needs `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`.
3. For the cross-check suite, point `--suite` at a checkout of Kev's `evals/v4/transfer-v4` directory (not redistributed here).

## The humanness experiment

Ten models (Opus 5.5, Sonnet 5, Haiku 4.5, Fable 5.1, Opus 4.6, OpenAI Codex, OpenCode big-pickle, qwen3:8b, hermes3:8b, gemma4:e2b) each rewrote the article's opening paragraph to sound human while keeping every fact ([`brief.txt`](humanness/brief.txt), [`versions.json`](humanness/versions.json)). We added two deliberately extreme controls ([`controls.json`](humanness/controls.json)) and asked Kev-4B and Jev three questions about each: was it written by a human, how natural does it sound, and which of the ten sounds most human (averaged over ten rotations of the option order). Rerun it against any endpoint with [`humanness/judge.py`](humanness/judge.py).

**Kev could not tell:** it scored the stiff and casual controls within 0.014 of each other. **Jev could:** 0.25 against 0.59 on the human question, and 0.14 against 0.85 on naturalness. See [`results-kev-4b-4bit.json`](humanness/results-kev-4b-4bit.json) and [`results-jev.json`](humanness/results-jev.json). This is one small experiment, not a benchmark.

## Caveats

One GPU, one machine, synthetic decision tasks. Your own decisions may rank these tools differently, so test on a labelled set from your domain before choosing. Latency is one request at a time and includes a local HTTP round trip; Jev's includes the internet round trip from our test machine. All seven projects were days old when tested and are changing quickly.

We are not affiliated with TypeSafe or with any of the projects tested. Jev and TypeSafe are TypeSafe's names; "System 1" refers to the general idea of fast, intuitive decisions.
